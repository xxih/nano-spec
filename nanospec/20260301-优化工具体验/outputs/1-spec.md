# 规格说明：工具体验优化（spec.init 简化 + CLI 易用性提升）

## 背景与目标

当前任务为 `nanospec/20260301-优化工具体验`，`brief.md` 明确了两类改进诉求：
1. `/spec.init` 不再做“是否初始化”的环境检测，默认在可执行命令的环境中直接走创建任务逻辑。
2. CLI 体验优化：`nanospec new` 无参数进入交互式输入（支持默认名直接回车），并为常用命令提供简写别名（至少覆盖 `switch -> s`）。

结合项目现状：
- `src/static/commands/spec.init.toml` 目前仍包含“先检测是否初始化、再决定 init/new”的分支逻辑。
- `src/commands/new.ts` 当前无参时直接使用“待命名”，不会进入交互输入。
- `src/index.ts` 当前未提供主命令 alias，用户必须输入完整命令名。

目标：
- 统一 `/spec.init` 为“创建任务入口”语义，减少无效环境判断。
- 降低 CLI 录入成本，提升高频命令可达性。
- 保持与现有命令体系兼容，不破坏已有流程和测试稳定性。

## 核心组成

```text
工具体验优化
├── A. /spec.init 流程简化（模板改造）
├── B. nanospec new 无参交互化（命令行为改造）
├── C. CLI 常用命令简写（命令注册改造）
└── D. 文档与测试同步（README + CHANGELOG + 单测）
```

### A. /spec.init 流程简化（模板改造）

交付物表现：
- `spec.init` 模板移除“检测 `<config_dir>/AGENTS.md` 再决定是否初始化”的流程。
- `/init` 只承担“提取任务意图并创建任务”的职责。
- 信息不足时仍要求先追问，不直接创建泛化任务名。

验收标准：
- 模板中不再出现“未初始化时执行 nanospec init”的决策分支。
- 模板仍保留“无法提取任务名时先澄清”的硬约束。
- 模板中的示例与输出说明与新职责一致。

### B. `nanospec new` 无参交互化（命令行为改造）

交付物表现：
- 执行 `nanospec new`（不带参数）时，进入交互输入框。
- 输入框预填默认值“待命名”，直接回车可创建默认任务名。
- 用户输入自定义名称后按回车，使用自定义名称创建任务。

验收标准：
- 无参时会触发交互式输入，而不是直接静默创建。
- 回车默认值、空白输入回退默认值、自定义输入三种路径行为可预测。
- 现有带参 `nanospec new <name>` 行为不变。

### C. CLI 常用命令简写（命令注册改造）

交付物表现：
- 为主命令提供可记忆的短别名，至少支持 `nanospec s` 等价于 `nanospec switch`。
- 别名配置集中在 CLI 注册层，避免分散在业务命令实现中。

验收标准：
- `switch` 命令具备 `s` 别名。
- 其他高频命令具备短别名并可通过程序注册信息验证。
- 别名能力不影响原命令名可用性。

### D. 文档与测试同步（README + CHANGELOG + 单测）

交付物表现：
- README 的命令表体现 `new` 的交互行为与命令别名。
- CHANGELOG 的 Unreleased 记录本次已交付项。
- 单测覆盖模板变化、`new` 交互行为、命令 alias 注册。

验收标准：
- 受影响文档已更新且与实际行为一致。
- 新增或更新测试在本地通过。
- 无新增未说明的行为破坏。

## 成功标志

- `/spec.init` 聚焦“创建任务”，不再出现多余初始化分支。
- 用户可用 `nanospec s` 快速切换任务。
- 用户执行 `nanospec new` 无参数时获得交互提示，并可直接回车创建默认任务。
- README、CHANGELOG、测试与实现保持一致。

## 约束与注意

> 必须遵守的限制条件

- 风格/规范：遵循现有 TypeScript/CLI 代码风格；`1-spec.md` 不使用 checklist 语法。
- 依赖项：沿用现有 `inquirer` 与 `commander`，不新增第三方依赖。
- 兼容性：保持现有命令全名可用，别名仅做增强不做替换。
- 测试约束：新增功能必须补充单测，并覆盖关键分支。
- 文档约束：影响用户行为时同步更新 `README.md`，并检查 `CHANGELOG.md`。
