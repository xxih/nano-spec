# 方案：工具体验优化实现方案

## 方案概述

本任务属于代码实施类任务，采用“模板规则调整 + CLI 行为增强 + 文档测试收口”的顺序推进。先稳定流程定义，再落地命令行为，最后通过测试与文档统一口径。

## 详细执行方案

1. 调整 `/spec.init` 模板语义
- 修改 `src/static/commands/spec.init.toml`，移除环境检测和初始化分支。
- 保留任务名提取与澄清机制，确保“信息不足不创建任务”的防线不退化。
- 同步更新模板回归测试断言，防止旧逻辑回流。

2. 增强 `nanospec new` 无参交互
- 在 `src/commands/new.ts` 引入无参分支：调用 `inquirer.prompt` 询问任务名。
- 设置默认值“待命名”，并对空白输入做回退处理。
- 保持带参路径不受影响。

3. 引入命令简写能力
- 重构 `src/index.ts`，提取 `createProgram()` 以便测试命令注册信息。
- 为主命令增加 alias（含 `switch -> s`），并让 bin 入口显式 parse。
- 增加 CLI 注册测试，校验别名映射存在且稳定。

4. 同步文档与变更记录
- 更新 `README.md` 的命令表和 `new` 使用说明。
- 更新 `CHANGELOG.md` Unreleased，记录本次完成项。

5. 验证与收尾
- 运行变更相关单测（`new`、模板、CLI 注册）。
- 任务完成后回写 `outputs/3-tasks.md` 勾选状态，确保可恢复。

## 风险与应对

- 风险：CLI 入口重构导致可执行文件不再自动 parse。
- 应对：同步修改 `bin/nanospec.js`，并通过测试/手动命令验证入口行为。

- 风险：`inquirer` 交互在测试环境挂起。
- 应对：单测中显式 mock `inquirer.prompt`，覆盖无参路径。
