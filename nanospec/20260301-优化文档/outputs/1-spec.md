# 规格说明：项目文档体系优化与口径统一

## 背景与目标

当前任务目录为 `nanospec/20260301-优化文档`。结合 `brief.md` 与项目现状，本需求定义为“对现有文档体系进行修改型优化”，而非新增功能开发。

项目现状（与本需求直接相关）：
- 文档入口主要集中在 `README.md`，但存在重复章节与重复命令说明。
- 维护者资料原位于 `docs/`，需改造为内部开发指南目录并与用户文档解耦。
- 项目已有 `CHANGELOG.md`，但文档更新与变更记录之间的联动规则未在规格层面明确。

目标：
- 建立清晰、可维护的文档信息架构，使用户能快速找到“该看哪份文档”。
- 统一 README、内部开发指南、命令说明的口径，降低冲突与重复。
- 为后续文档迭代提供稳定验收标准，减少“改一处漏一处”。

## 核心组成

```text
文档体系优化与口径统一
├── README 主入口重构（修改）
├── guides 内部开发指南编排（修改）
├── 命令与工作流文档口径统一（修改）
├── 变更记录联动机制（新增规则）
└── 文档质量基线（新增验收标准）
```

### 1. README 主入口重构（修改）

交付物表现：
- README 作为“唯一主入口”，保留项目介绍、快速开始、核心命令索引、跳转链接。
- 重复章节被合并，同一主题只保留一个权威描述位置。
- 文案以中文为主，结构清晰，用户可快速定位核心信息。

验收标准：
- README 中同一层级的同名功能章节不再重复出现。
- 快速开始包含可直接执行的最小流程（初始化、创建任务、进入工作流）。
- README 明确定位为用户入口，仅链接必要的用户信息与 `CHANGELOG.md`。

### 2. guides 内部开发指南编排（修改）

交付物表现：
- `guides/` 中每份文档有明确主题职责，避免与 README 内容大段重复。
- 内部文档集合具备统一导航视图（在 `guides/README.md` 体现），便于维护者按场景查阅。
- 历史文档保留，但通过索引说明其定位（入门/开发/发布/CI-CD）。

验收标准：
- `guides/` 下已有文档均可从内部索引导航到达。
- 每篇专题文档在开头能体现适用场景或目标读者。
- README 与 guides 不再出现同一主题的冲突描述。

### 3. 命令与工作流文档口径统一（修改）

交付物表现：
- 文档中的 CLI 命令、slash command 名称、工作流阶段命名保持一致。
- 对关键命令提供统一的“用途 + 触发时机”描述，避免多版本说法并存。
- 文档对“默认行为”和“可选行为”有清晰区分。

验收标准：
- 文档中列出的命令名称与项目当前支持命令一致。
- 工作流顺序（spec → plan → execute）在各文档中表述一致。
- 不再存在同一命令在不同章节中含义冲突的情况。

### 4. 变更记录联动机制（新增规则）

交付物表现：
- 文档变更与 `CHANGELOG.md` 建立最小联动规则，保证可追溯。
- 读者可从主入口快速定位版本变更记录。
- 规则覆盖“何种文档变更需要记录、记录粒度如何定义”。

验收标准：
- 文档体系中明确存在 `CHANGELOG.md` 的入口链接。
- 文档更新规则可区分“结构性调整”与“文字润色”两类变更。
- 团队可据此判断某次文档变更是否需要进入 changelog。

### 5. 文档质量基线（新增验收标准）

交付物表现：
- 形成统一质量标准，用于后续文档修改的自检。
- 标准覆盖结构清晰度、信息一致性、可导航性、术语一致性。
- 质量标准可直接用于评审，不依赖个人经验。

验收标准：
- 主入口到关键信息（安装、命令、工作流、配置）路径清晰。
- 中文信息完整且表达清晰，不再依赖双语并行结构。
- 文档链接可达且无明显失效跳转。

## 成功标志

- 新用户可在主入口完成从安装到首个任务创建的路径理解。
- 维护者可快速找到内部开发指南（调试、发布、CI/CD）。
- 文档中的命令与流程口径一致，重复与冲突显著减少。
- 文档变更具有可追溯性，后续维护成本下降。
- 对齐产物完整：`outputs/1-spec.md`、`outputs/2-plan.md`、`outputs/3-tasks.md` 均存在且口径一致。

## 约束与注意

> 必须遵守的限制条件

- 风格/规范：遵循现有项目文档语气与中文单语结构；禁止在 `1-spec.md` 使用 Markdown checklist 语法。
- 依赖项：依赖当前仓库已有命令能力与现有文档资产，不引入新的产品功能作为前置条件。
- 兼容性：本任务定位为文档优化，不改变 CLI 行为与既有工作流语义。
- 执行边界：当前按 `brief.md` 执行文档修正（结构去重、导航优化、口径校对），不扩展为功能开发。
- 项目约束：遵守仓库 AGENTS 规则；`src` 目录下不新增名为 `AGENTS.md` 的文档。
- 范围约束：当前范围仅包含 README 精简与内部指南整理（`guides/`），若新增范围需先走对齐流程。
