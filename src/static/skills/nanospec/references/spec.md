# 规格

## 目标

把模糊需求转化为清晰、有边界、可验收的 `outputs/1-spec.md`。

## 输入

1. 用户显式指定的任务目录或任务名，或 `.nanospec/.current`。
2. `brief.md` / `prd.md`。
3. `assets/*`。
4. `alignment.md`（若存在）。
5. 当前工作区现状。

## 执行流程

1. 读取任务输入，并结合工作区现状判断这是新增、修改还是重构。
2. 明确背景、目标、核心组成、成功标志、约束与注意事项。
3. 聚焦“交付物最终应该表现成什么”，而不是提前展开实现方案。
4. 识别冲突、歧义或缺失，并将需要确认的问题追加到 `alignment.md`。
5. 将最终规格写入 `outputs/1-spec.md`。

## 输出约束

- `1-spec.md` 禁止使用 Markdown 复选框。
- 每个需求都必须有可验收的成功标志。
- 若仓库已有定制格式，优先遵循项目级 AGENTS 规则。

## 规则

- 聚焦“交付什么”，不要提前展开实现细节。
- 每条需求都必须有可验证的验收证据。
- 不确定处必须显式记录，不能默认拍板。
